# Supabase PostgreSQL 마이그레이션

파일명 순서대로 Supabase SQL Editor 또는 PostgreSQL 클라이언트에서 적용합니다. 각 파일은 트랜잭션을 포함하고 반복 실행할 수 있으며 기존 질문과 추첨 이력을 삭제하지 않습니다.

1. `202611120001_core.sql`: 테이블/참가자/질문/추첨 이력, FK·인덱스·RLS, 초기 TABLE 01–03. 기존 추가 테이블은 보존합니다.
2. `202611120002_visitor_identity.sql`: 방문자 연결, 서버 세션 토큰 해시, 작성자 스냅샷, 추첨 멱등 키.
3. `202611120003_question_decoration.sql`: nullable JSONB `questions.decoration`. 기존 질문은 NULL로 유지하고, 새 질문은 편지지·대상 뱃지·스티커 위치를 저장합니다.

업데이트 순서는 **DB → FastAPI → 프론트엔드**입니다. 프론트엔드는 Supabase에 직접 연결하지 않습니다. 운영 DB 비밀키와 연결 문자열은 백엔드에만 둡니다.

참가자는 REST API에서 그룹을 추가·이름 변경할 수 있습니다. 이름은 trim 후 1–30자이며 제어 문자를 거절합니다. 이름이 바뀌어도 테이블 ID와 번호는 유지됩니다. 동시 그룹 생성은 PostgreSQL 트랜잭션 advisory lock으로 번호를 발급합니다.

스티커는 서버에 등록된 ID만 허용하고, 대상 뱃지와 꾸미기 스티커의 중심 좌표는 편지지 기준 0–1 비율로 저장합니다. 꾸미기 스티커는 최대 3개, 중복 ID·잘못된 좌표·임의 이미지 URL은 거절합니다. 추첨/이력/최근 결과에 같은 데이터를 반환합니다.

임시 로컬 `net_test` PostgreSQL에서 마이그레이션 반복 적용·기존 데이터 보존·20개 동시 추첨·20개 동시 테이블 생성 테스트를 수행할 수 있습니다. 운영 DB에는 테스트를 실행하지 않습니다.
